# Выкладка SC Companion на текущий Wispbyte

Подготовка пакета не означает его установку. Активный экземпляр по контексту —
`community-hub /7f303fa2`; free и локальный Trader остаются резервами.
Перед выкладкой уточни актуальный активный экземпляр, чтобы не запустить два.

## До остановки

1. Проверь SHA256 ZIP и его `release-manifest.json`. Пакет только с кодом.
2. Используй обычный входящий webhook SC Patches в рабочем «📢sc-патчи».
   Проверь его прежние IDs/ключ; новый webhook для обновления не нужен.
3. Закрытый `patches-config.json` создаётся по примеру, сначала с enabled=false.
   URL только в закрытом файле вне Git/образа; права каталога700, файлов600.
4. Сохрани старые app.py, весь trader/ и requirements.txt, текущую версию кода
   и свежую защищённую копию данных. Подключения, переписки и master.key сохраняются
   вместе. Секреты не добавляй в обычный release ZIP.

## Установка

1. Останови только активный paid экземпляр. Убедись, что резервы не запущены.
2. Не удаляя operator-config.json, trader-data и прежние подключения, извлеки
   code-only ZIP в рабочую папку /home/container. Сохрани PY_FILE=app.py и прежние
   environment/requirements параметры. requirements.txt совпадает с прежним lock;
   новых сторонних runtime-зависимостей нет.
3. Проверь `python -m companion.worker --check`. Это не старт бота.
4. При подготовленном новостном канале включи enabled=true и выполни
   `python -m patch_alerts.app check-target --config patches-config.json`:
   должен вернуться verified с точными IDs. Эта команда не публикует пост.
5. Запусти только paid. При новой CAPTCHA требуется подтверждение текущей проверки
   по правилам браузерного управления. При первом включении RSS-скан тихо запоминает
   историю; при обычном обновлении прежняя история/очередь сохраняются целиком.

## Проверка после запуска

- Console: обычный Trader инициализирован/Discord ready; первая полная сверка UEX
  завершена без потери подключений. Счётчики сравниваются с фактическим предвыкладочным
  снимком, а не со старыми числами из документов.
- `python -m companion.status`: отдельно trader и patches. Новости должны иметь
  свежую source-проверку, без unknown/blocked. Первое отсутствие новых постов нормально.
- Подтверди source/Docker/cloud по manifest/module hashes; новый код на диске сам
  по себе не доказывает, что запущен именно он. Запиши время нового запуска и версии.
- Реальные сделки/объявления/переписки не используй для тестовых отправок.
  Дополнительный демонстрационный пост только по отдельному разрешению.

## Возврат

Останови paid, верни старые app.py, trader/ и requirements.txt и прежнюю startup
настройку. Новости отключаются enabled=false либо отсутствующим default конфигом.
Торговая схема/данные этим выпуском не мигрируют; восстанавливать старую БД поверх
новых реальных переписок не требуется. Не удаляй текущую БД/master.key.
Состояние patches-data сохрани: после возврата к новому коду оно предотвращает повторы.
Не сбрасывай состояние unknown без проверки канала.

Локально испытай поставку и возврат на отдельном demo-каталоге. Production rollback
и запуск облака не считаются проверенными по одному локальному smoke.

## Обновление 0.1.1 до 0.1.2: упоминание роли

Сохрани `patches-data` целиком: сброс или повторная подготовка истории не нужны.
Добавь в действующий `patches-config.json` поле
`"mention_role_id": "1506239876511694928"` («Космопират»); интервал остаётся 600 секунд.
Роль должна разрешать упоминания. Значение необязательно: без него поведение прежнее.
После штатной остановки установи код и запусти один paid-экземпляр. В новой строке
запуска news должны быть poll_seconds=600 и этот mention_role_id.
Упоминание применяется к новым отправкам; старые сообщения и unknown не переотправляй.
Демонстрационный реальный пинг не входит в обычную проверку установки.

## Обновление первого запуска 0.1.0 до 0.1.1

В 0.1.0 реальная RSS с датами в category могла сохраняться как история без
распознанных событий. Перед обновлением сохрани patches-data. Только если очередь
и история отправок пусты, после остановки переименуй старый каталог в резервный,
чтобы 0.1.1 тихо запомнил реальную ленту заново. Не сбрасывай sent/pending/unknown
или другую существующую очередь: для неё требуется отдельная сверка состояния.
Каталог, БД и master.key торговца при этой операции не меняются.
