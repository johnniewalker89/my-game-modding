# SC Companion

Один процесс для двух модулей Star Citizen:

- **SC Trader / SCT** — существующий Discord-бот торговли UEX.
- **SC Patches / SCP** — собственный новостной поток и входящий webhook,
  без второго bot user/Gateway и без модели/переводчика.

Торговый код и его TRADER_* конфигурация не меняются. Новости явно включаются
отдельным файлом; по умолчанию выключены. Состояние модулей хранится раздельно.
Ошибка чтения RSS или webhook-доставки отражается в статусе новостей, не завершает
торговый worker. Первый успешный запуск новостей запоминает историю без рассылки.

## Комплект для хостинга

`build_hosting.py --out <новый-путь-в-local>.zip` собирает только код и документы.
Результат содержит `app.py`, `trader/`, `patch_alerts/`, `companion/`, прежние
`requirements.txt`, пример новостной конфигурации и SHA256-манифест.
Рабочие `operator-config.json`, `trader-data`, `master.key`, webhook URL и состояние
новостей в ZIP не включаются. Подробные шаги установки и возврата: [DEPLOYMENT.md](DEPLOYMENT.md).

Штатный Wispbyte `PY_FILE=app.py` сохраняется. Общий entrypoint загружает прежний
`operator-config.json` с переменными окружения. Если файла нет, использует environment
как обычный Docker worker. Опциональный `SC_COMPANION_OPERATOR_CONFIG_FILE` выбирает
другой закрытый файл. Права торговых данных остаются прежними: каталог700/файлы600.

## Конфигурация новостей

Создай `patches-config.json` по примеру; полный секретный URL хранится отдельно
в `private/sc-patches-webhook.url`, вне исходников и образа. Относительные пути
в конфигурации считаются от её папки. Обязательны точные ID webhook/канала/сервера.
По умолчанию конфигурация называется `patches-config.json`; другой путь задаётся
через `SC_PATCHES_CONFIG_FILE`. Явно указанный отсутствующий файл считается ошибкой.
Для отключённого модуля ключ не читается и запросов нет.
Настройки и ключ загружаются при старте. После их изменения нужен штатный
перезапуск единственного активного процесса; команды сверки очереди работают без него.

Команды на хостинге из папки app.py:

```sh
python -m companion.worker --check
python -m patch_alerts.app check-target --config patches-config.json
python -m companion.status
```

Первая проверяет только конфигурацию/импорты и не запускает бота.
Вторая выполняет только GET-метаданных webhook, без сообщения.
Для запуска используется `python app.py`; не запускай параллельно старый worker.
В установленном Docker доступны также `sc-companion-worker`, `sc-companion-check`
и `sc-companion-status`.

## Уведомления и отказы

Предупреждение, перенос, начало и окончание работ — отдельные короткие посты.
При выпуске ищется точная версия в официальном индексе CIG; при сбое или отсутствии
точной ссылки явно показывается «общий список». Полные заметки не извлекаются.
Парсер принимает только явные формулировки RSI Status; ранний сигнал не гарантирован,
если CIG не указал подходящие дату/время или не опубликовал запись в этом источнике.

Перед POST проверяются ID, затем сохраняется inflight. `wait=true` возвращает
message ID; ответ сверяется с webhook/каналом и payload. При429 ожидается
Retry-After, при400/401/403/404 требуется исправление настройки/причины.
Обрыв,5xx или падение после POST оставляют **unknown** и блокируют новые отправки
до сверки. Автоматического «ровно один раз» при неопределённом HTTP-исходе не обещаем.
Накопленный устаревший этап не отправляется после известного нового этапа.

Состояние новостей видно в `patches-data/worker-status.json` и общей status-команде.
Для разбора unknown прочитай ID уведомления и проверь канал. Затем выбери ровно
одну операцию; эти команды не требуют остановки торговца:

```sh
python -m patch_alerts.app reconcile --config patches-config.json --notice-id ID --decision sent --message-id DISCORD_ID
python -m patch_alerts.app reconcile --config patches-config.json --notice-id ID --decision discard
python -m patch_alerts.app reconcile --config patches-config.json --notice-id ID --decision retry --confirm-not-sent
```

`sent` подтверждает существующий пост GET-запросом; `discard` пропускает уведомление;
`retry` допускает новую отправку в следующем цикле только после явного подтверждения,
что прежней отправки не было. При занятой краткой блокировке повтори команду позже.

## Локальная сборка и проверка

Compose в этой папке собирает отдельный `sc-companion:hosting-candidate`.
Он не использует текущий production том или Discord-токен. Данные candidate
выделены в отдельный volume, автозапуск выключен. Секреты/боевые настройки не входят
в build context. Запуск с настоящими ключами разрешается отдельно для выбранного
экземпляра; для проверки достаточно demo/network-none.
