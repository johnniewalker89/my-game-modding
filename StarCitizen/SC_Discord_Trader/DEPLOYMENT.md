# Развёртывание SC Discord Trader

Первая установка и заполнение `.env` — в [README](README.md#установка-своего-бота).
Команды ниже выполняются из папки `compose.yaml`; нужен Docker Compose 2.24+.

## Требования к хостингу

Постоянно работающий процесс, постоянный диск и исходящие HTTPS/WebSocket к
Discord, UEX и переводчику. Засыпание и временный диск не подходят.
Обычный запуск — один worker без веб-порта; домен не нужен.
Для одного Discord-бота запускай только один экземпляр.

Ключи оператора передавай через закрытый `.env` на сервере или переменные
окружения хостинга. В Git и образ они не входят. Два личных ключа UEX
участники вводят через форму бота. Правила хранения — в [SECURITY.md](SECURITY.md).

Для личного напоминания о хостинге задай `TRADER_HOSTING_REMINDER_USER_ID`
(свой Discord ID) и `TRADER_HOSTING_REMINDER_URL` (ссылка на панель).
Бот напишет после первого запуска и затем раз в 10 дней; срок хранится в базе.
При закрытых личных сообщениях повторит попытку через сутки. Выключенный бот
напоминать не сможет. По умолчанию функция отключена.

## Обновление и настройки

Сначала сохрани прежний код/образ и резервную копию данных по инструкции ниже.
Получи новую версию исходников, сохранив свой `.env`, затем выполни:

```sh
docker compose build bot
docker compose up -d --no-build bot
```

После изменения только `.env` достаточно `docker compose up -d bot`:
обычный `restart` новые значения из файла не применяет.
Для отката используй прежний код/образ; при несовместимом формате базы
восстанови соответствующую резервную копию.

## Проверка и перезапуск

В Discord администратору доступна **/статус**, без Discord — команды:

```sh
docker compose ps
docker compose exec bot sc-discord-trader-status
docker compose logs --tail 50 bot
```

Состояние обновляется раз в минуту. `ok` — связь с Discord и успешные сверки UEX;
`degraded` — проверь логи: возможны проблемы соединения или внешнего API.
**/статус** также показывает число запросов Discord с запуска и за ≈10 минут, коды ошибок и последний отказ.
При429 повторы ограниченной операции приостанавливаются на срок `Retry-After`, затем возобновляются автоматически.
Срок паузы виден в статусе, операция и доступные сведения о лимите — в журнале.
После HTTP-ошибки состояние требует внимания не менее пяти минут и до конца активной паузы.
Счётчики сбрасываются при перезапуске.
Фоновый опрос UEX идёт раз в 10 секунд; роль участника при пустой сверке проверяется
не чаще раза в пять минут. Действия игрока и доставка нового входящего проверяют
роль заново. После возврата снятой роли фоновый опрос может ждать до пяти минут;
действие игрока с проверкой доступа обновляет результат сразу.

Запуск и остановка: `docker compose start bot` / `docker compose stop bot`.
В Compose автоперезапуск отключён. На хостинге настрой перезапуск после сбоя
и ограничение размера логов. При нехватке RAM процесс может быть завершён системой;
если это повторяется, увеличь лимит. Неопределённый результат отправки или публикации
сначала проверь на UEX, прежде чем повторять действие.

## Резервная копия и перенос

1. Останови `bot` и скопируй **весь том `trader_data`**: базу, `master.key` и
   остальные файлы. Отдельно сохрани закрытый `.env` и версию кода/образа.
   Храни копии зашифрованными и с ограниченным доступом, вне Git.
2. На новой машине подготовь ту же версию кода и защищённо передай `.env`.
   Выполни `docker compose build bot`, затем `docker compose create bot` —
   контейнер будет создан без запуска.
3. Восстанови файлы в его том `/data`. Пользователь контейнера
   `10001:10001` должен иметь к ним доступ. Сохрани ограниченные права на `master.key`.
4. Убедись, что прежний экземпляр остановлен. Запусти новый через
   `docker compose start bot`, проверь **/статус**, **/меню** и прежние переписки.

База и `master.key` нужны вместе; без ключа участникам придётся подключаться заново.
Не используй `docker compose down -v` для остановки — команда удаляет том с данными.
Очистка старых текстов и черновиков описана в [README](README.md#ключи-данные-и-лицензия).

## Другие режимы

- **Python-хостинг:** установи пакет `pip install .`, задай `TRADER_*` в закрытых
  переменных окружения, `TRADER_DATA_DIR` — на постоянном диске. Запуск:
  `sc-discord-trader-worker`; проверка: `sc-discord-trader-status`.
  Сам `.env` без Compose не читается.
- **LibreTranslate:** в `.env` задай `TRADER_TRANSLATOR=libretranslate`.
  Запуск всей группы: `docker compose --profile local-translation up -d --build`,
  остановка: `docker compose --profile local-translation stop`.
  Первый запуск скачивает модели EN/RU. При переходе на Groq останови `translator`.
- **Azure:** задай `TRADER_TRANSLATOR=azure`, `TRADER_AZURE_KEY` и при необходимости
  `TRADER_AZURE_REGION`; запуск как обычно.
- **HTTP-стенд:** `docker compose -f compose.yaml -f compose.http.yaml up -d bot`.
  Доступен только локально: http://127.0.0.1:8765, проверка — `/health`.
  Для демо без реальных UEX/Discord оставь `TRADER_MODE=demo` и режимы `test`.
  Возврат к worker: `docker compose up -d bot`.

Перед переносом на выбранный хостинг проверь сохранность диска, перезапуск
после сбоя и восстановление из копии.
