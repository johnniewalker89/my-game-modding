# SC Discord Trader

Бот для переписок UEX Marketplace в Discord с переводом английский ↔ русский.
Каждый участник подключает свой аккаунт UEX; доступ разрешается выбранной роли сервера.

## Возможности

- Новые сообщения UEX автоматически появляются в приватной ветке сделки.
  В карточке видны собеседник, качество и цена за единицу, если они указаны на UEX.
- Ответ по-русски в ветке переводится и отправляется собеседнику по-английски.
- Оригинал сообщения можно посмотреть отдельной кнопкой.
- Объявления WTB/WTS/WTT создаются и удаляются из Discord: товар, количество,
  цена за единицу, качество, условия и необязательное фото JPG/PNG до 7 МиБ.
- Постоянная личная подпись добавляет перед описанием ссылку на магазин и текст
  по-английски. Оба поля необязательны и сохраняются для подключённого UEX.
- «Найти товар» показывает непроданные предложения UEX по пять карточек:
  название открывает объявление, ник продавца — его магазин; доступное фото видно миниатюрой.
  Локация — отдельная строка под запасом, без подписи; если её нет — «Не указано».
  Можно задать минимальное качество и сортировать по цене либо качеству.
- Ветки можно убрать в архив и вернуть. Новое входящее вернёт ветку автоматически.
  При закрытии сделки на UEX ветка уходит в архив с сохранением истории.

## Как пользоваться

1. Открой панель бота или введи **/меню**.
2. Нажми **«Подключить UEX»** и введи в личной форме оба своих ключа:
   Secret Key из [аккаунта UEX](https://uexcorp.space/account/) и токен
   [своего API-приложения](https://uexcorp.space/api/apps/).
3. **«Мои сделки»** открывает переписки; пиши обычным сообщением в своей ветке.
4. **«Объявления» → «Создать объявление»**: найди товар по оригинальному названию,
   заполни условия, проверь перевод и подтверди публикацию. Цена указывается
   за одну выбранную единицу; срок предложения можно не задавать.
   Место по умолчанию — By arrangement, его можно изменить без перевода.
   Если качество не заполнено, строки Quality в описании не будет.
5. **«Объявления» → «Подпись»**: один раз сохрани ссылку на магазин и/или текст.
   Русский текст переводится при сохранении; результат виден сразу и в предпросмотре
   нового объявления. Чтобы убрать блок, очисти его поле; оба пустых поля отключат
   подпись. Изменения действуют на будущие публикации, существующие карточки остаются.
6. **«Найти товар»** в **/меню** или **/поиск**: введи название и необязательное
   минимальное качество. Выбери точный товар, если найдено несколько вариантов.
   Выбери сортировку в выпадающем списке; стрелки под ним листают предложения.
   Качество можно сортировать от высокого к низкому и от низкого к высокому.
   Карточки без указанного качества в обоих случаях идут последними; с заданным
   минимумом они исключаются. Если качество нигде не указано, остаются две
   ценовые сортировки. Новый поиск обновляет снимок предложений.
   Если запас не указан (UEX возвращает 0), количество не показывается; проданные
   объявления отсеиваются по отдельному признаку Sold Out. Фото продавца
   отображается миниатюрой, если UEX предоставляет доступную ссылку.
   Для видимой пятёрки бот уточняет ссылку на оригинал со страницы объявления:
   карточки остаются компактными, а по нажатию открывается доступное полное фото.
   Ссылки кэшируются на пять минут; при сбое уточнения остаётся фото из API.
7. **«Отключить UEX»** на общей панели, в **/меню** или **/отключить** удаляет оба
   сохранённых ключа после подтверждения. История переписок остаётся.

Первая строка панели — подключение и отключение UEX; вторая — сделки,
поиск и объявления. Общая панель обновляется на месте при запуске бота;
**/панель** администратора обновляет её или размещает первую панель.

Личное меню, подключение и подтверждение отключения видны только тебе. Приватные ветки также доступны администрации
с соответствующими правами. После простоя кнопки личного меню убираются;
чтобы открыть его снова, введи **/меню**.

## Установка своего бота

Нужен Docker с Linux containers и **Docker Compose 2.24+**.
На Windows подходит Docker Desktop. Команды выполняются из папки этого README.

1. Создай приложение в [Discord Developer Portal](https://discord.com/developers/applications).
   Получи **Bot Token**, включи **Message Content Intent**.
   Пригласи бота со scopes **bot** и **applications.commands**, код прав **360777370624**.
   Administrator боту не нужен. Разреши ему просмотр настроенного канала,
   сообщения, файлы/ссылки и создание/управление приватными ветками.
2. Выбери текстовый канал и роль участников. Участникам нужны просмотр канала
   и отправка сообщений в ветках. Скопируй ID сервера, канала и роли.
3. Получи токен [API-приложения UEX](https://uexcorp.space/api/apps/)
   для общего каталога и ключ [Groq](https://console.groq.com/keys) для перевода.
4. Скопируй **.env.example** в **.env**, только если своего .env ещё нет.
   Заполни в нём:

| Настройка | Значение |
| --- | --- |
| TRADER_MODE | live |
| TRADER_DISCORD_TOKEN | Bot Token твоего Discord-приложения |
| TRADER_UEX_APP_TOKEN | Токен приложения UEX для общего каталога |
| TRADER_GUILD_ID | ID Discord-сервера |
| TRADER_CHANNEL_ID | ID текстового канала |
| TRADER_ROLE_ID | ID разрешённой роли |
| TRADER_TRANSLATOR | groq |
| TRADER_GROQ_API_KEY | Твой ключ Groq |
| TRADER_GROQ_MODEL | openai/gpt-oss-120b |
| TRADER_UEX_SEND_MODE | production — реальные ответы собеседникам |
| TRADER_UEX_LISTING_MODE | production — реальное создание и удаление объявлений |

В шаблоне безопасные режимы demo/test. Режимы сообщений и объявлений включаются
отдельно: test проверяет запрос, но не подтверждает реальную отправку/публикацию.
Личные два ключа каждого участника вводятся через бота, не в общий .env.

```sh
docker compose config --quiet
docker compose up -d --build bot
```

Обычный запуск — экономичный worker без веб-порта. Администратор вводит
**/статус** для проверки, затем **/панель** в выбранном канале.
Участники подключаются кнопкой панели. Обе команды доступны только администратору.

Логи и состояние доступны без Discord:

```sh
docker compose logs --tail 50 bot
docker compose exec bot sc-discord-trader-status
```

Для повторного запуска: **Docker Desktop → Containers → sc-discord-trader-local
→ ▶ у bot-1**; остановка — **■**. Или используй docker compose start bot / stop bot.
Автозапуск отключён: само включение Docker не поднимает бота.

Обновление, перенос на сервер, резервные копии и другие переводчики описаны
в [инструкции развёртывания](DEPLOYMENT.md), включая необязательный HTTP-стенд.

## Ограничения

- Первое обращение продавцу отправь на сайте UEX, открыв объявление из карточки
  поиска; дальше можно общаться в Discord.
- Поиск показывает продажи из текущего ответа API UEX, до 1000 строк на товар.
  При достижении предела бот предупреждает, что ответ может быть неполным.
  Цены сортируются отдельно внутри каждой валюты и единицы измерения.
  Фото появляется, когда API предоставляет ссылку на него. Активность продавца
  в первой версии не используется. Sold Out исключаются автоматически.
- Редактирование опубликованной карточки, завершение сделки, остатки и
  «Готов торговать» меняются на сайте UEX.
- Скрытые на UEX / Aborted переписки могут оставаться в «Моих сделках»:
  проверенный API не даёт надёжного признака для их фильтрации.
- Новое объявление может ждать модерации. Список API может не показывать
  скрытые или ожидающие проверки карточки, созданные на сайте.
  Ранее активная карточка исчезает из списка бота, если UEX перестал её возвращать,
  и появляется снова, если вернётся в активный каталог.
- Между проходами опроса пауза 10 секунд; запросы, нагрузка и квоты добавляют задержку.
- В переписке пересылается только текст, исходящий ответ — до 2000 символов.
  Перевод может ошибаться: оригинал доступен. При ошибке перевода отправки нет;
  при неизвестном результате отправки сначала проверь UEX, затем решай, повторять ли её.

## Ключи, данные и лицензия

.env и данные не входят в Git или образ. Подключения и история хранятся
в постоянном томе; личные ключи UEX зашифрованы. Для восстановления нужны база
и master.key вместе. Не удаляй том командой docker compose down -v.
Groq получает переводимые тексты; владелец сервера хранения имеет доступ к данным.
Раз в сутки бот очищает локальные тексты через 14 дней после обнаружения закрытия
сделки, черновики и их фото — через 3 дня после создания. История Discord остаётся.
Активные переписки и незавершённые отправки не очищаются. Старый «Оригинал»
загружается с UEX только по нажатию; если площадка его не отдаёт, бот сообщит об этом.
