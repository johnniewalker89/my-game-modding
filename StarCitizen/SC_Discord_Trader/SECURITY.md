# Ключи и личные данные

## Настройка своего экземпляра

В Git входит только `.env.example` с пустыми полями ключей. Каждый оператор
создаёт свой локальный `.env` и сам получает токен Discord-бота, токен приложения
UEX для публичного каталога и ключ выбранного переводчика. Чужие действующие
ключи вместе с исходниками не передаются.

`.env`, его резервные копии, ключевые файлы, базы и журналы исключены из Git.
Docker получает только разрешённые входные файлы сборки. В образ ключи не
встраиваются: Compose передаёт настройки из локального `.env` при запуске.
Не публикуй вывод `docker compose config`, `docker inspect`, переменные окружения
или диагностические архивы без проверки — они могут содержать значения ключей.
Gitignore не удаляет уже закоммиченные секреты из истории.

Ограничь доступ к `.env` средствами ОС. На хостинге используй его защищённые
настройки окружения/хранилище секретов, а не файлы в публичном репозитории.
Для передачи ключа администратору используй защищённый канал передачи секретов;
в обычный чат, issue, PR, README и скриншот ключи не вставляй.

## Подключение участника

Участник вводит свой Secret Key UEX и токен своего API-приложения только в
личной форме бота. Общедоступное сообщение и ветка сделки для этого не подходят.
Discord получает содержимое формы: это не сквозное шифрование. Доверять нужно
также оператору экземпляра бота; администратор хоста с доступом к базе и
мастер-ключу технически может расшифровать сохранённые ключи.

В базе оба ключа хранятся зашифрованными. Команда `/отключить` удаляет оба
сохранённых ключа подключения, оставляя историю сделок. Это не отзыв ключей
на UEX и не гарантированное стирание прежних данных из SQLite/WAL/резервных копий.
Для отзыва используй управление ключами самой площадки.

## Перенос и резервные копии

Технический runtime-status-live.json содержит только состояние процесса,
подключения Discord и агрегаты сверок, без ключей, имён участников и текстов.
Команда Discord `/статус` доступна только администратору своего сервера и отвечает
лично, в том числе при вызове через MCP. Не добавляй пользовательские данные
в диагностические файлы и логи. HTTP-стенд необязателен и привязан к localhost.

Локальные тексты закрытых сделок очищаются через 14 дней после того, как бот
увидел закрытие. Черновики с фото — через 3 дня после создания; незавершённые
и неопределённые отправки сохраняются. История Discord и служебные идентификаторы
доставки остаются. Для старого оригинала бот по нажатию обращается к UEX,
но не сохраняет полученный текст повторно и не отправляет его переводчику.
Очистка не означает гарантированное стирание из свободных страниц SQLite,
журнала WAL, Discord, UEX или ранее сделанных резервных копий.

Постоянный том содержит базу `trader-live.sqlite3` и `master.key`; история
и содержимое базы могут быть конфиденциальными. Храни резервные копии
зашифрованными и с ограниченным доступом, вне Git и публичных архивов.
Для штатного восстановления нужны и база, и её мастер-ключ; делай согласованную
копию SQLite (включая корректную обработку WAL) или останавливай сервис на время
копирования. Отдельно переноси конфигурацию окружения защищённым способом.

Лицензия требует предоставлять применимые исходники и инструкции, а не реальные
ключи, пользовательские базы или личную переписку. Публикуй шаблоны настроек.

## Если ключ оказался раскрыт

Сначала отзови/перевыпусти его у провайдера и обнови локальную настройку или
подключение. Удаление файла или коммита само по себе старый ключ не обезвреживает.
Не отправляй действующий ключ вместе с сообщением об уязвимости.
