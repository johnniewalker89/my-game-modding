# SC Patches · модуль SC Companion

Отдельный модуль уведомлений о LIVE-обновлениях Star Citizen. Русские шаблоны и
ссылка на официальные заметки; модели и переводчика нет.

Локальный `serve` по-прежнему **ничего не отправляет в Discord**. Отдельный
`worker` с явно включённой закрытой конфигурацией ведёт очередь и доставляет
новые уведомления через собственный webhook. Общий launcher SC Companion
запускает его рядом с торговым worker в одном процессе.
Локальная страница показывает те же
webhook payload, которые используются при доставке.
Четыре примера вымышленные и помечены «ДЕМО». Компактный формат пока проверен
в локальном предпросмотре; прежний формат участвовал в ручном Discord-тесте.

## Запуск

Из этой папки: `docker compose build`, затем `docker compose up -d --no-build`.
Предпросмотр: http://localhost:8789. Остановка: `docker compose stop`.
Запускается только новостной MVP; торговый бот не импортируется и не подключается.
Данные — в отдельном Docker volume; секреты и рабочие файлы не входят в исходники.
Порт опубликован только на 127.0.0.1, автоперезапуска нет.

## Что уже работает

- Чтение публичной RSS RSI Status раз в 90 секунд с `If-Modified-Since`.
- Первое чтение запоминает историю; последующие выявляют существенные изменения.
- Сохранение состояния между перезапусками; одинаковое событие не дублируется.
- Предупреждение, перенос, начало и завершение работ — отдельные новые сообщения.
  Одинаковое содержимое повторно не публикуется. Edit не используется для оповещения:
  ручной тест на клиенте пользователя подтвердил отсутствие повторного уведомления.
- Компактный формат: заголовок с версией, 1–2 строки о времени/оценке/ссылке,
  без отдельных полей. Окончание не повторяет всю карточку начала работ.
- Если CIG явно назвал длительность, показывается его оценка «до»/«около».
  Ориентир окончания рассчитывается только при известном начале; время публикации
  не подменяет фактическое начало работ. Завершение показывается отдельно от оценки.
- Обычное завершение обслуживания не выдаётся за выпуск новой версии игры.
- Ошибка источника видна в статусе, история при этом не сбрасывается.
- Сохранённая очередь, подтверждение POST по message ID и проверенным webhook/channel;
  неизвестный исход не повторяется автоматически. HTTP429 ждёт Retry-After.
  Старый накопленный этап не публикуется после известного более нового этапа.

Парсер намеренно ограничен явными формулировками RSS. Распознаёт назначенное
время только при полной дате и UTC, не угадывает расписание. PTU, будущая дата
публикации, неясный текст и неподходящие incidents пропускаются. Это не полный
мониторинг всех ранних объявлений CIG. Пропущенный сигнал возможен.

Перед доставкой выпуска модуль ищет точную версию в официальном индексе CIG.
При отсутствии/сбое точной ссылки кнопка-текст честно обозначает «общий список».
Полный текст заметок не парсится и не передаётся модели.

## Проверка

`python -m unittest discover -s tests -v` в Python 3.12+.
Для проверки установленного образа: `docker run --rm --network none --workdir /tmp
sc-patch-alerts:mvp-local python -m unittest discover -s /app/tests -v`.

`sc-patch-alerts demo` печатает примеры; `sc-patch-alerts scan --data-dir /data`
делает одну проверку RSS. `serve --offline` показывает примеры без сети.
Текущая health-проверка подтверждает доступность preview; состояние источника
отдельно показывается в `/api/status`. Общая инструкция включения/установки и
ручной сверки unknown — в соседнем SC_Companion/README.md и DEPLOYMENT.md.
Готовая кодовая интеграция не означает, что модуль уже установлен в облаке.
